# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Nuxt 4 app (Nuxt UI 4, Tailwind 4, `@nuxt/image`) for browsing the public Rick and Morty API. Package manager is pnpm, Node version in `.nvmrc`.

## Commands

```bash
pnpm dev                                  # dev server on http://localhost:3000
pnpm build                                # production build (runs vue-tsc type check, typeCheck: true)
pnpm lint / pnpm lint:fix                 # eslint (config generated by @nuxt/eslint into .nuxt/)
pnpm test                                 # vitest in watch mode
pnpm vitest run                           # all tests once
pnpm vitest run shared/utils/__tests__/resource-url.test.ts   # single file
pnpm vitest run -t "should accept numeric id"                 # single test by name
pnpm test:coverage
```

## After every change

Run all four checks and fix any failures before reporting the work as done:

```bash
pnpm lint                                                  # eslint
pnpm prettier --check "{app,server,shared}/**/*.{ts,vue}"  # formatting (fix with --write)
pnpm nuxi typecheck                                        # vue-tsc
pnpm vitest run                                            # all tests
```

The pre-commit hook runs `lint-staged` (prettier + eslint --fix) on `app/**/*.{ts,vue}` only. Prettier: tabs, single quotes, print width 100, tailwind class sorting.

## Architecture

**Data flow:** page → `useNuxtApp().$api.<repo>.<method>()` → `$fetch` with `baseURL: '/api'` → Nitro proxy `server/api/[...path].ts` → `runtimeConfig.apiBaseUrl` (rickandmortyapi.com).

- `app/plugins/fetch.ts` builds a single `$fetch` instance and provides `$api = { characters, episodes }`, which are class-based repositories from `app/repositories/`. Repositories take the fetch instance in their constructor, so tests can inject a `vi.fn()`.
- The server proxy is the only path to the upstream API. It whitelists paths with `ALLOWED_PATH` (`character|episode|location` + optional `/1,2,3`) and returns 404 for everything else. It is a `defineCachedEventHandler` (24h, SWR) and maps upstream `FetchError` status codes through. Any new resource type must be added to that regex.
- The upstream API returns a single object, not an array, when asked for one id (`/character/5`). The repositories' `getByIds` normalize this. Keep that in mind for any multi-id request.
- Resources reference each other by URL (`episode.characters: string[]`). `shared/utils/resource-url.ts#getIdFromResourceUrl` turns them into ids for `getByIds`.

**Detail pages** (`app/pages/character/[id].vue`, `app/pages/episode/[id].vue`) follow one pattern:
1. `definePageMeta({ validate: validateIdParam('X not found') })` rejects non-numeric ids with 404 before fetching.
2. The main entity is loaded via `useRequiredAsyncData` (`app/composables/`). It throws a fatal 404 when there is no data or upstream returns 404, and a fatal "Couldn't load x" error otherwise.
3. Related entities are loaded with `useLazyAsyncData` and render skeleton / `UAlert` with retry / list states.
4. `useSeoMeta` uses getter functions so meta updates reactively.

`experimental.typedPages` is on: use named routes like `useRoute('character-id')` and `{ name: 'character-id', params: { id } }`.

**Shared code:** `shared/` (alias `#shared/...`) holds API types (`shared/types.ts`) and utils used by both app and server.

**Components:** components are imported explicitly in `<script setup>` (e.g. `import BaseMediaCard from '~/components/base/base-media-card.vue'`); only Nuxt UI `U*` components and Nuxt built-ins are used via auto-import. `base/` holds generic building blocks (`BaseMediaCard` is the shared card shell for character and episode cards). Custom SVG icons are in `app/assets/icons` and are used as `custom:<name>`. Theme overrides (secondary = amber) are in `app/app.config.ts`.

## Testing

- Vitest with `environment: 'nuxt'` (`@nuxt/test-utils`), `globals: true`, setup in `setup.ts` (mocks `#app`).
- Tests live in `__tests__/` next to the code they cover, named `<file>.test.ts`.
- Component tests use `shallowMount` from `@vue/test-utils` and stub Nuxt UI components (`UCard`, `ULink`, `UIcon`, `NuxtLink`) with simple templates. Elements are selected by `data-test-id` attributes (snake_case, e.g. `character_card`), so keep those attributes when changing templates.
- Test names follow the `it('should ...')` style.

## Conventions

- Commits use Conventional Commits (`feat(scope):`, `refactor(ui):`, `chore(release):`). `CHANGELOG.md` is generated from them, so scopes and types matter.
